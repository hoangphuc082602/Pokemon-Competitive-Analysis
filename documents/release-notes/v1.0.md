# v1.0 — static web app on GitHub Pages

**Live demo:** <https://hoangphuc082602.github.io/Pokemon-Competitive-Analysis/>

v1.0 publishes the analysis as a static site, built and deployed by GitHub Actions (ADR-013). The site reads a frozen data snapshot (2026-10-14: 2,547,946 completed VGC battles, 5,095,892 player-battles, 9 regulations from Reg D 2023 to Champions Reg M-A 2026) and never queries a database.

## Features

- **Meta Overview.** Team usage per form, filtered by regulation × rating band (one band at a time, never summed): `n`, usage, win rate against the band's own baseline, 95% Wilson interval, lead rate, typing and base stat total. Rows with `n < 100` are hidden. Per species: most frequent partners with lift (co-occurrence, not synergy), team-level matchups against the log5 expectation, monthly usage trend (`tail` months disclosed and left out) and Tera. Filters live in the URL.
- **Insights.** Four findings on Reg F 2026, each stating population, rating band, `n` and baseline, separating fact, calculation and interpretation, and linking to the Overview view that reproduces it.
- **Damage Calculator.** The project's Python damage engine running in the browser via Pyodide 0.26.4 (≈ 5.6 MB on first use, cached afterwards): level-50 stats, damage range, % HP and a KO estimate. A banner lists the mechanics not modelled.
- **Team Builder.** Up to six Pokémon (form, ability, held item, nature, EVs / IVs, moves) with the item clause; named teams saved in the browser (no account, no server); versioned share links in the URL fragment; team analysis (speed tiers, stat-based roles, weakness / resistance table, synergy tally); Showdown paste export.
- **Web export.** `python.analytics.export_web` and `python.analytics.calc_master` apply the metric rules at export time: allow-listed columns only, usernames / replay ids / player-level fields make the export fail, `n ≥ 100`, band baselines, one file per regulation × band, PokéAPI licence notice shipped with the data.
- **CI / CD.** pytest (no database), Vitest and the production build on every pull request; deployment to GitHub Pages on `main`.

## Known limitations

- Data is a frozen snapshot of public Showdown ladder replays: a self-selected sample, not tournament play; Bo3 games are not independent; the month is the replay's upload month.
- Statistics are descriptive. Lift is co-occurrence, not synergy; matchups are team-level, not on-field; win rates with and without Tera are not comparable.
- Masked forms (e.g. Urshifu) are known only when the Pokémon entered the field; forms missing from the master data stay at species level.
- The damage engine does not model spread moves, critical hits, weather, burn, item / ability damage modifiers, Tera STAB or stat stages.
- Learnsets are Scarlet / Violet only and alternate forms borrow their species' default abilities and learnset; regulation item legality is not checked.
- The recommender (Word2Vec) is a baseline with no hold-out evaluation and is not part of the site.

## Next steps

- **v1.1:** recommender with hold-out evaluation; Power BI dashboard; remaining team analysis (threats, validated synergy); damage mechanics, one per change; learnsets and abilities per regulation.
- **v1.2:** weekly crawl + parse job and a refreshed snapshot.
